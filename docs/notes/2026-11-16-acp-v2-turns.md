# ACP v2 turns

2026-11-16. Experimental, for clients that negotiate ACP protocol version 2
(draft). v1 sessions behave as before.

In v2 the `session/prompt` result only acknowledges that the prompt was
inserted. The turn ends with a `session/update` whose update is a
`state_update` with `state: "idle"`, usually with a `stopReason`.

- The host reads `protocolVersion` from the agent's `initialize` result.
  Nothing in the spec selects v2: the host follows what client and agent
  negotiated.
- With v2, a prompt marks the session running from when it is sent (the
  agent may acknowledge before reporting `running`). `running` and
  `requires_action` keep it running, a rejected prompt clears it. Welcome's
  `busy` is set while running.
- An idle `state_update` after foreground work sends `turn_end` to the
  controller, after the update itself, with result `{"stopReason": ...}`,
  the same shape a v1 prompt result gives. With no controller it waits in
  the turn_end queue as v1's does. A successful v2 prompt result is never
  turned into `turn_end`.
- The journal renderer prints the idle update as the turn end.
- `Protocol` is unchanged: no wire message between client and host changed
  shape.
